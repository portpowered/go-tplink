# Lighting operations

Lighting calls use `passthrough`. The outer `params.requestData` is a string
containing a JSON object under
`smartlife.iot.smartbulb.lightingservice`. Authenticated requests send the
token in the `token` URL query parameter.

Example outer request for reading state:

```json
{
  "method": "passthrough",
  "params": {
    "deviceId": "<bulb-id>",
    "requestData": "{\"smartlife.iot.smartbulb.lightingservice\":{\"get_light_state\":\"\"}}"
  }
}
```

Decoded command: `{"smartlife.iot.smartbulb.lightingservice":{"get_light_state":""}}`.

A successful setter acknowledgement is wrapped in the outer cloud response;
`responseData` remains a JSON-encoded string:

```json
{"error_code":0,"result":{"responseData":"{\"smartlife.iot.smartbulb.lightingservice\":{\"transition_light_state\":{\"err_code\":0}}}"}}
```

The client decodes that string before checking the nested command result.

## Read light state

`GetLightState` takes `tplink.GetLightStateRequest{Auth, DeviceID}` and returns
`tplinkmodels.LightState` and an `error`. Decoded `result.responseData` contains
`smartlife.iot.smartbulb.lightingservice.get_light_state` with these typed
fields:

| JSON field | Go field | Type | Documented meaning / request range |
| --- | --- | --- | --- |
| `on_off` | `OnOff` | `int` | State; request values 0 or 1 |
| `brightness` | `Brightness` | `int` | Setter uses 0–100 |
| `hue` | `Hue` | `int` | Setter uses 0–360 |
| `saturation` | `Saturation` | `int` | Setter uses 0–100 |
| `color_temp` | `ColorTemp` | `int` | Kelvin; supported range varies |
| `mode` | `Mode` | `string` | Returned text; client assigns no meaning |
| `err_code` | `ErrCode` | `int` | Nonzero becomes device error |

The recorded-in-repo light response fixture is synthetic.
The setter ranges shown here are documented inputs, not local validation:
the Go methods pass integer values to the device without checking bounds.

## Scalar getters

`GetBrightness`, `GetColorTemp`, and `GetColor` all send the same
`get_light_state` command as `GetLightState`. Each request contains only `Auth`
and `DeviceID`; each method returns the result and an `error`.

| Method | Returned Go value |
| --- | --- |
| `GetBrightness` | `BrightnessResult{Brightness int}` |
| `GetColorTemp` | `ColorTempResult{ColorTemp int}` |
| `GetColor` | `ColorResult{Hue int, Saturation int}` |

## Setters

Every setter below uses decoded
`smartlife.iot.smartbulb.lightingservice.transition_light_state` and returns
an `error`. Successful command response is an acknowledgement with integer
`err_code` and optional `err_msg` under `transition_light_state`.

| Method and request fields | Decoded command parameters | Documented input; no local bounds check |
| --- | --- | --- |
| `SetBrightness`: `Auth, DeviceID, Brightness` | `{"brightness":50}` | Integer 0–100 |
| `SetColorTemp`: `Auth, DeviceID, ColorTemp` | `{"color_temp":4000}` | Kelvin; no client bounds check |
| `SetColor`: `Auth, DeviceID, Hue, Saturation` | `{"hue":240,"saturation":80}` | Hue 0–360; saturation 0–100 |
| `SetLightState`: `Auth, DeviceID, State` | Caller map, such as `{"on_off":1,"brightness":75,"hue":120,"saturation":50}` | Map is not validated |

All parameter objects above are nested beneath
`{"smartlife.iot.smartbulb.lightingservice":{"transition_light_state":...}}`.
Known `State` fields are `on_off` (integer 0 or 1), `brightness` (integer
0–100), `color_temp` (integer Kelvin; no client-enforced range), `hue` (integer
0–360), and `saturation` (integer 0–100). These are documented request values;
the typed setters do not validate them locally. Values depend on device support.
The Go wrapper marshals the map as JSON; an unmarshalable value returns an
invalid-request error. Unknown fields can be passed through, but this client
does not document or validate their device meaning.
