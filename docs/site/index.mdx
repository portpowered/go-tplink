# Guides

Every supported operation uses an HTTP `POST` to the configured cloud base URL.
The outer JSON `method` selects login, device enumeration, or passthrough.
Device commands use two JSON layers: `params.requestData` is a string containing
the command document, and `result.responseData` is a string containing the
device response document. These guides show both the outer envelope and the
decoded inner shapes.

| Goal | Go method | Guide |
| --- | --- | --- |
| Create a cloud session | `Login` | [Authentication](/docs/guides/authentication) |
| List devices and inspect advertised capabilities | `GetDevices` | [Devices](/docs/guides/devices) |
| Turn plugs on/off, read state, reboot, rename | `TurnOn`, `TurnOff`, `GetPowerState`, `Reboot`, `SetAlias` | [Plug and device operations](/docs/guides/plugs) |
| Read or change bulb state | `GetLightState`, `GetBrightness`, `GetColorTemp`, `GetColor`, `SetBrightness`, `SetColorTemp`, `SetColor`, `SetLightState` | [Lighting operations](/docs/guides/lighting) |
| Handle cloud, device, or transport failures | Any operation | [Errors and token handling](/docs/guides/errors) |

## Evidence

The payloads describe shapes assembled and decoded by this client. Checked-in
replay fixtures are **synthetic**: their source cannot be verified, and they
are not live TP-Link captures. This is not a vendor-issued protocol
specification. Device behavior can vary by model, region, account, and firmware.
